Miért
          hasznos a JSON formázó?

        
A JSON (JavaScript Object Notation) a webes alkalmazások leggyakrabban
          használt adatcsere-formátuma. API válaszok, konfigurációs fájlok és NoSQL adatbázisok tárolására egyaránt
          alkalmas. A nyers, tömörített JSON azonban nehezen olvasható emberi szemmel.

        
Ez az eszköz automatikusan behúzásokat és színes szintaxis kiemelést ad a
          struktúrának, így gyorsan észreveheted a hiányzó vesszőket, zárójeleket vagy idézőjeleket. Használd REST API
          válaszok debuggolásához, konfigurációk ellenőrzéséhez, vagy tanuláshoz.

        
A
          validátor funkció sor-szintű hibajelzést ad, így pillanatok alatt megtalálod a szintaktikai problémákat
          anélkül, hogy külön IDE-t kellene indítanod.

          szükség JSON és XML konvertálásra?

        
A modern REST API-k és microservice-ek többsége JSON-t használ, de sok legacy

Mi az a Base64
          kódolás?

        
A Base64 egy bináris adat szöveges ábrázolási módja, amelyet elsősorban olyan
          helyeken használnak, ahol csak ASCII szöveges tartalom továbbítható biztonságosan. A 64 karakteres ábécé (A–Z,
          a–z, 0–9, +, /) minden bináris információt reprezentálni képes.

        
Gyakori alkalmazási területei közé tartozik az e-mail mellékletek MIME kódolása, a
          CSS-ben vagy HTML-ben inline használt képek (data URI scheme), valamint REST API-kban küldött fájlok és
          tokenek. Fejlesztők naponta találkoznak Base64 stringekkel JWT tokenekben és adatURL-ekben.

        
Ez az
          eszköz szöveget és helyi fájlokat egyaránt képes gyorsan kódolni és visszafejteni. A fájl encode funkció
          automatikusan felismeri a MIME típust, így készen áll a beillesztésre webes környezetbe.

Mikor kell
          URL-t kódolni vagy dekódolni?

        
Az URL-ekben bizonyos karakterek — mint a szóköz, az ékezetes betűk, a perjel
          vagy az ampersand — nem szerepelhetnek nyers formában, mert félreértelmezhetik a böngésző vagy a szerver a cím
          szerkezetét. Az encodeURIComponent szabvány szerinti kódolása biztosítja a helyes értelmezést.

        
Használd ezt az eszközt API hívások query paramétereinek előkészítéséhez,
          összetett keresési URL-ek összeállításához, vagy form adatok biztonságos továbbításához. A dekódoló funkcióval
          visszaállíthatod az eredeti, olvasható szöveget egy kódolt linkből.

        

          Különösen hasznos frontend és backend fejlesztőknek egyaránt, akik gyakran dolgoznak OAuth redirect URI-kkel,
          deep linkekkel és query string-ekkel.

Mi az a UUID és
          mikor használják?

        
Az UUID (Universally Unique Identifier) egy 128 bites azonosító, amely
          statisztikailag garantáltan egyedi marad még globálisan, elosztott rendszerekben is. A v4 verzió teljesen
          véletlenszerűen generálódik kriptográfiailag biztonságos algoritmusokkal.

        
Fejlesztők adatbázis elsődleges kulcsokként (PostgreSQL, MongoDB), session
          azonosítókként, fájlnévként, vagy mikroszolgáltatásokban entitás-azonosításhoz alkalmazzák. Az UUID-k előnye,
          hogy offline is generálhatók anélkül, hogy centralizált számlálóra lenne szükség.

        
Ez az eszköz
          egyszerre akár száz egyedi azonosítót is generálhat, és egy kattintással a vágólapra másolhatod az összeset.
          Tökéletes tesztadatok előállításához és prototípusok építéséhez.

Hogyan működik a
          JSON Web Token?

        
A JWT (JSON Web Token) egy nyílt szabvány (RFC 7519), amely kompakt és önálló módon
          biztosít információátvitelt a felek között. Három ponttal elválasztott részből áll: header (algoritmus és
          token típus), payload (állítások / claims) és signature (digitális aláírás).

        
Gyakran használják autentikációhoz és autorizációhoz modern webes és mobil
          alkalmazásokban. A szerver a titkos kulcsával aláírja a tokent, és a kliens minden kérésnél elküldi. A szerver
          ellenőrzi az aláírást, majd a payloadból kiolvassa a felhasználói jogosultságokat és lejárati időt.

        
Ez az eszköz
          dekódolja a token Base64Url kódolt header és payload részét, így gyorsan ellenőrizheted a lejárati időt (exp),
          a kiállítót (iss) és az egyéb claim-eket anélkül, hogy külön JWT könyvtárat importálnál a projektedbe.

Mi az a reguláris
          kifejezés?

        
A reguláris kifejezések (regex vagy regexp) formális nyelvek, amelyek szövegminták
          leírására szolgálnak. Segítségükkel kereshetsz, validálhatsz, szűrhetsz és cserélhetsz szövegrészeket
          rendkívül hatékonyan, akár nagy méretű log fájlokban is.

        
Gyakori felhasználási területei: e-mail cím és telefonszám validáció, dátum formátum
          ellenőrzés, HTML tag-ek kinyerése, log fájlok szűrése, kódrefaktorálás IDE-kben, és input mezők ellenőrzése
          webes űrlapokon. A JavaScript, Python, Java és szinte minden modern nyelv beépített regex támogatással
          rendelkezik.

        
Ez az
          eszköz valós időben, színes kiemeléssel mutatja a találatokat, és támogatja az összes JavaScript regex flag-et
          (global, case-insensitive, multiline, dotAll, unicode, sticky). Így azonnal láthatod, ha a mintád helyes,
          mielőtt beillesztenéd a produkciós kódodba.

Miért népszerű
          a Markdown?

        
A Markdown egy könnyűsúlyú jelölőnyelv, amelyet John Gruber 2004-ben alkotott
          meg. Célja, hogy olvasható, nyers formában is tiszta szövegként írható legyen, majd egyszerűen strukturált
          HTML-re konvertálható. A szintaxis minimális, így a tartalomra koncentrálhatsz a formázás helyett.

        
A GitHub README fájlok, dokumentációk (GitBook, Docusaurus), blogbejegyzések
          (Jekyll, Hugo), jegyzetelő alkalmazások (Notion, Obsidian) és chat üzenetek (Discord, Slack) alapértelmezett
          vagy támogatott formátuma. A .md kiterjesztés ma már szinonimája a fejlesztői dokumentációnak.

        
Ez az
          előnézeti eszköz GitHub-stílusú CSS renderelést biztosít, beleértve a kódblokkokat, táblázatokat, idézeteket
          és listákat. Így pontosan láthatod, hogyan fog kinézni a dokumentumod publikálás előtt, és gyorsan javíthatod
          a szintaktikai hibákat.
